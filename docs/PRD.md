# PRD: Rider Voice MVP

## 1. 제품 개요

Rider Voice MVP는 카카오로 로그인한 사용자가 음식점을 찾아 픽업 과정에서 관찰한 경험을 구조화된 리뷰로 기록하는 서비스다.

이번 MVP의 목적은 방문 인증이나 공개 리포트를 완성하는 것이 아니라, 음식점 선택부터 비공개 리뷰 작성·조회·수정·삭제까지의 기본 흐름을 검증하는 것이다.

MVP 리뷰는 방문이 인증된 리뷰가 아니다. 작성자 본인만 볼 수 있으며 외부 공개나 통계 집계에 사용하지 않는다.

## 2. 해결하려는 문제

- 배달 과정에서 경험한 픽업 환경을 항목별로 기록할 간단한 도구가 부족하다.
- 일반 음식점 리뷰는 맛과 소비자 경험 중심이어서 픽업 과정의 운영 경험을 구조화하기 어렵다.
- 처음부터 방문 인증, 공개 집계와 운영 절차를 모두 구현하면 핵심 작성 경험을 검증하기 전에 MVP가 지나치게 커진다.

## 3. MVP 사용자

- **리뷰 작성자**: 카카오로 가입하고 음식점을 선택해 비공개 리뷰를 작성한다.
- 소비자, 음식점 관계자와 관리자는 현재 MVP 사용자가 아니다.
- 카카오 로그인은 계정 식별 수단이며 사용자의 라이더 신분이나 음식점 방문을 증명하지 않는다.

## 4. 핵심 사용자 흐름

### 4.1 로그인

1. 사용자가 카카오 소셜 로그인을 완료한다.
2. 신규 사용자는 필수 약관에 동의한다.
3. 활성화된 사용자에게 서비스 세션을 발급한다.

### 4.2 음식점 검색과 등록

1. 로그인 사용자가 음식점명 또는 주소로 검색한다.
2. 서버는 내부 음식점과 카카오 로컬 API의 장소 후보를 반환한다.
3. 사용자가 카카오 장소를 선택한다.
4. 내부에 없는 장소라면 클라이언트가 원래 검색어와 선택한 `kakaoPlaceId`를 전송한다.
5. 서버는 같은 검색을 다시 수행해 장소 ID가 결과에 포함되는지 확인하고 음식점을 한 번만 등록한다.
6. 이미 등록된 장소라면 기존 음식점을 반환한다.

사용자는 음식점명, 주소와 좌표를 임의로 확정하거나 수정할 수 없다. 서버 검색 결과에서 확인되지 않은 장소 ID는 등록할 수 없다. 최초 선택 사용자는 음식점의 소유자나 관리자가 되지 않는다.

### 4.3 비공개 리뷰 CRUD

1. 로그인 사용자가 내부 `restaurantId`를 선택한다.
2. 6개 평가 항목을 모두 선택하고 선택 의견을 입력한다.
3. 서버는 사용자와 음식점 조합당 리뷰를 하나만 생성한다.
4. 사용자는 자신의 리뷰 목록과 상세 내용을 조회할 수 있다.
5. 사용자는 자신의 리뷰를 수정하거나 삭제할 수 있다.

다른 사용자의 리뷰는 조회·수정·삭제할 수 없다. 현재 MVP에는 음식점별 공개 리뷰 조회 API가 없다.

## 5. 리뷰 입력 규칙

### 평가 값

각 항목은 다음 값 중 하나를 사용한다.

| API 값 | 화면 표시 |
| --- | --- |
| `VERY_GOOD` | 매우 좋음 |
| `GOOD` | 좋음 |
| `NEEDS_IMPROVEMENT` | 개선 필요 |
| `MAJOR_IMPROVEMENT` | 큰 개선 필요 |
| `NOT_OBSERVED` | 관찰하지 못함 |

### 평가 항목

1. 픽업 공간 청결
2. 포장 안정성
3. 주문 준비 상태
4. 주문 확인·전달 정확성
5. 직원 응대
6. 라이더 존중

6개 항목은 모두 필수다. 의견은 선택 사항이며 최대 200자다.

## 6. 제품 규칙

- 음식점은 카카오 장소를 기준으로 식별한다.
- 같은 카카오 장소는 내부에 중복 등록하지 않는다.
- 사용자 한 명은 음식점 한 곳에 리뷰 하나만 작성할 수 있다.
- 두 번째 생성 요청은 기존 리뷰를 덮어쓰지 않고 충돌 오류를 반환한다.
- 리뷰 변경은 전체 별점 집합과 의견의 유효성을 다시 검사한다.
- 삭제는 MVP에서 실제 삭제로 처리한다.
- 리뷰와 카카오 계정 정보는 공개하지 않는다.
- 종합 별점, 음식점 순위와 공개 리포트를 제공하지 않는다.

## 7. MVP 범위

### 포함

- 카카오 로그인, 약관 동의와 서비스 세션
- 카카오 장소 검색
- 선택된 장소의 내부 음식점 멱등 등록
- 로그인 사용자의 비공개 리뷰 생성·목록·상세·수정·삭제
- 6개 구조화 평가와 최대 200자 선택 의견
- REST API, OpenAPI와 권한·유효성 검증 테스트

### 제외

- 라이더 자격 확인과 방문 증빙
- 이미지 업로드, OCR와 배달 앱 파싱
- `WriteGrant`와 인증 리뷰 전환
- 리뷰 공개, 음식점별 집계와 리포트
- 관리자 검수, 신고와 음식점 정정 요청
- 지역 파일럿 제한과 리워드
- React Native 또는 별도 웹 화면
- Docker, Testcontainers, AWS 인프라와 배포

## 8. 완료 기준

- 카카오 로그인 사용자가 음식점을 검색하고 선택한 장소를 중복 없이 등록할 수 있다.
- 사용자가 6개 평가와 선택 의견으로 리뷰를 생성할 수 있다.
- 사용자가 자신의 리뷰만 목록·상세 조회, 수정과 삭제할 수 있다.
- 사용자와 음식점 조합당 리뷰 하나라는 규칙을 DB 제약과 애플리케이션 정책으로 보장한다.
- 공개 API 응답과 OpenAPI 문서가 실제 DTO 계약과 일치한다.
- 인증되지 않은 요청, 타인 리뷰 접근, 잘못된 평가 값과 200자 초과 의견을 테스트한다.

## 9. 후속 로드맵

MVP 사용 흐름이 검증된 뒤 필요성을 다시 확인하고 순서대로 결정한다.

1. 배달 완료 증빙과 방문 인증
2. 비공개 리뷰의 인증 리뷰 전환 정책
3. 최소 표본 기반 음식점 리포트
4. 자유 의견 검수, 신고와 정정 절차
5. 실제 사용자용 웹 또는 React Native 클라이언트
6. 배포 및 운영 인프라
