# PRD: Rider Voice 공개 리뷰 MVP

## 1. 서비스 소개

Rider Voice는 음식점의 배달 준비와 픽업 환경에 대한 리뷰를 모아 보여주는 서비스입니다.

일반 음식점 리뷰에서는 음식의 맛이나 소비자 응대는 확인할 수 있지만, 포장이 안정적인지, 주문이 제때 준비되는지, 픽업 공간이 깨끗한지 같은 정보는 알기 어렵습니다. Rider Voice는 이런 정보를 정해진 항목으로 모아 소비자에게 제공합니다.

소비자는 로그인 없이 리뷰를 볼 수 있고, 카카오 로그인 사용자는 리뷰를 작성할 수 있습니다.

## 2. 해결하려는 문제

- 소비자가 음식점의 배달 준비 상태나 픽업 환경을 미리 알기 어렵습니다.
- 배달 앱의 브랜드명과 실제 픽업 장소가 다르거나, 한 장소에서 여러 브랜드를 운영하는 경우가 있습니다.
- 현장에서 알게 된 정보를 일정한 기준으로 공유할 공개 공간이 부족합니다.
- 초기부터 복잡한 방문 인증을 요구하면 리뷰를 모으기 어렵습니다.

초기 MVP에서는 인증 기능보다 실제로 리뷰가 모이고 소비자에게 도움이 되는지를 먼저 확인합니다.

## 3. 사용자

- **소비자**: 로그인 없이 음식점을 검색하고 공개 리뷰와 항목별 평가 결과를 확인합니다.
- **리뷰 작성자**: 카카오 로그인 후 리뷰를 작성하고 자신의 활성 리뷰를 관리합니다.
- **관리자**: 신고를 검토하고 잘못된 음식점 정보를 정정합니다.

## 4. 꼭 지켜야 할 신뢰 원칙

카카오 로그인은 같은 사용자를 구분하기 위한 수단일 뿐, 그 사람이 실제 라이더인지 또는 음식점을 방문했는지를 증명하지 않습니다.

모든 공개 리뷰와 평가 결과에는 다음과 같은 안내를 표시합니다.

> 이 정보는 카카오 로그인 사용자가 작성했으며, 라이더 신분과 실제 방문 여부는 인증되지 않았습니다.

## 5. 주요 사용 흐름

### 5.1 음식점 검색

1. 소비자가 음식점명이나 주소를 검색합니다.
2. 서비스에 등록된 음식점과 카카오 검색 결과를 함께 보여줍니다.
3. 아직 리뷰가 없는 음식점도 리뷰가 없다는 상태와 함께 보여줍니다.
4. 카카오 검색을 사용할 수 없으면 등록된 음식점만 보여주고 검색이 제한되었음을 알립니다.

### 5.2 로그인과 리뷰 작성

1. 사용자는 로그인할 때마다 카카오 계정을 다시 인증해 원하는 계정으로 로그인합니다.
2. 로그인 화면에서 카카오 로그인이 계정 식별 수단일 뿐 라이더 신분이나 실제 방문을 인증하지 않는다는 안내를 확인합니다.
3. 로그인 성공 후 브라우저의 안전한 쿠키로 Rider Voice 로그인 상태를 유지합니다.
4. 음식점, 방문 연월과 6개 평가 항목을 선택합니다.
5. 필요한 경우 200자 이내의 자유 의견을 작성합니다.
6. 정해진 평가와 자유 의견은 작성 직후 공개됩니다.

### 5.3 카카오에 없는 배달 브랜드 등록

작성자는 카카오 검색에 없는 브랜드도 다음 방법으로 등록하면서 첫 리뷰를 작성할 수 있습니다.

- 이미 등록된 픽업 장소에 새 배달 브랜드를 추가합니다.
- 주소 검색으로 실제 픽업 장소를 확인하고 새 배달 브랜드를 등록합니다.

사용자가 입력한 주소와 장소 정보는 그대로 믿지 않고 검색 결과를 다시 확인합니다. 음식점 등록에 실패하면 첫 리뷰도 등록되지 않습니다. 최초 등록자에게 음식점 소유권이나 수정 권한을 주지는 않습니다.

카카오 검색으로 등록한 음식점은 카카오 장소 ID를 음식점에 함께 저장해 같은 카카오 장소가 중복 등록되는 것을 막습니다. 주소로 수동 등록한 음식점에는 카카오 장소 ID가 없을 수 있습니다.

### 5.4 공개와 관리

- 브랜드와 픽업 장소의 평가 결과는 각각 서로 다른 작성자 5명부터 공개합니다.
- 5명 미만일 때는 결과 대신 현재 리뷰를 작성한 사람 수를 보여줍니다.
- 유효한 작성자가 다시 5명 미만이 되면 평가 결과도 다시 숨깁니다.
- 자유 의견을 수정하면 수정 내용이 즉시 공개됩니다. 단, 신고로 숨겨진 의견은 신고 처리 전까지 계속 숨깁니다.
- 신고가 접수되면 확인이 끝날 때까지 공개 의견만 숨기고 정해진 평가는 유지합니다.
- 문제가 의견에만 있으면 의견만 숨기고, 허위 작성이나 반복 도배라면 리뷰 전체를 공개와 집계에서 제외합니다.
- 관리자는 잘못된 이름, 픽업 장소와 폐업 정보를 정정하고 변경 기록을 남깁니다.

## 6. 리뷰 작성과 평가 규칙

- 한 사용자는 같은 음식점에 활성 리뷰를 하나만 가질 수 있습니다.
- 활성 리뷰가 있다면 새 리뷰 대신 기존 리뷰를 수정해야 합니다.
- 방문 연월은 이번 달 또는 지난달만 선택할 수 있으며 작성 후 바꿀 수 없습니다.
- 활성 리뷰만 수정하거나 삭제할 수 있고, 다른 사람의 리뷰나 비활성 리뷰는 수정·삭제할 수 없습니다.
- 삭제는 기록을 남기는 방식으로 처리하며 삭제된 리뷰는 사용자에게 보여주지 않습니다.
- 삭제되거나 전체 제외된 뒤에는 최초 작성일로부터 90일이 지나야 다시 작성할 수 있습니다.
- 삭제·전체 제외 리뷰도 계정당 최근 24시간 최대 10개의 작성 횟수에 포함합니다.

평가 항목은 다음 6개입니다.

| 구분 | 평가 항목 |
| --- | --- |
| 배달 브랜드 | 포장 안정성, 주문 준비 상태, 주문 확인과 전달 정확성 |
| 픽업 장소 | 픽업 공간 청결, 직원 응대, 라이더 존중 |

6개 항목은 모두 작성하며 `매우 좋음`, `좋음`, `개선 필요`, `큰 개선 필요`, `관찰하지 못함` 중 하나를 선택합니다. `관찰하지 못함`은 선택한 사람 수로는 보여주지만 평가 비율에서는 제외합니다.

한 작성자가 같은 픽업 장소의 여러 브랜드에 리뷰를 남긴 경우, 픽업 장소 결과에는 가장 최근의 유효한 리뷰 하나만 반영합니다.

## 7. MVP 범위

### 이번에 포함하는 것

- 카카오 로그인
- 로그인 없는 음식점 검색, 상세 정보와 공개 리뷰 조회
- 실제 픽업 장소와 소비자에게 보이는 배달 브랜드의 분리
- 카카오 장소 및 주소 검색을 이용한 음식점 등록
- 6개 평가 항목, 방문 연월과 200자 이내의 자유 의견
- 음식점별 활성 리뷰 1개와 90일 재작성 제한
- 작성자 5명부터 공개하는 브랜드 및 픽업 장소 평가 결과
- 자유 의견 신고와 사후 조치, 음식점 이름·픽업 장소·폐업 정보 정정
- 백엔드 Docker 이미지와 master 검증 성공 후 Docker Hub 게시 자동화
- 운영 DB 목표인 RDS MySQL 8.4.10과 동일한 버전의 CI 통합 검증
- Flyway versioned migration과 Hibernate schema validation을 이용한 운영 DB 변경 검증

### 이번에 포함하지 않는 것

- 라이더 신분이나 실제 방문 인증
- 실제 운영용 앱, 관리자 화면과 실행 서버 배포 작업
- Redis, Kafka, Elasticsearch 같은 추가 인프라
- Docker Compose, AWS 리소스 생성과 운영 환경 배포

## 8. 완료 기준

- 소비자가 로그인 없이 음식점을 검색하고 공개 리뷰를 볼 수 있어야 합니다.
- 로그인 사용자가 기존 음식점 또는 확인된 장소에 리뷰를 작성할 수 있어야 합니다.
- 같은 음식점의 활성 리뷰 중복과 삭제·전체 제외를 이용한 90일 제한 우회를 막아야 합니다.
- 정해진 평가와 자유 의견은 작성·수정 즉시 공개되어야 합니다.
- 브랜드와 픽업 장소의 결과가 각각 작성자 5명 기준에 맞게 공개되어야 합니다.
- `관찰하지 못함`이 평가 비율에서 제외되어야 합니다.
- 신고된 의견과 리뷰, 잘못된 음식점 정보를 관리자가 처리할 수 있어야 합니다.
- 모든 공개 리뷰와 평가 결과에서 미인증 정보라는 사실을 확인할 수 있어야 합니다.
- master 반영 전 백엔드·MySQL 통합 테스트와 컨테이너 기동 검증이 성공해야 하며, 성공한 백엔드 이미지만 Docker Hub에 게시되어야 합니다.
- MySQL 통합 검증은 운영 RDS 목표 버전인 MySQL 8.4.10을 사용해야 합니다.
- 완전히 빈 MySQL에 Flyway migration을 적용한 뒤 Entity, FK, unique와 index가 일치해야 합니다.
