# PRD: Rider Voice

## 1. 제품 개요

Rider Voice는 배달 완료 화면으로 음식점 방문을 인증한 사용자가 픽업 과정에서 직접 관찰한 운영 경험을 기록하고, 이를 음식점별 리포트로 제공하는 플랫폼이다.

서비스가 보장하는 것은 사용자의 직업 신분이 아니라 개별 리뷰의 방문 근거다. 따라서 공개 화면에서는 `인증된 라이더`보다 `방문 인증 리뷰`라는 표현을 사용한다.

> 소비자에게는 운영환경을 알 권리를, 배달 경험자에게는 안전하게 말할 권리를 제공한다.

## 2. 해결하려는 문제

### 리뷰 작성자

- 음식점에서 겪은 좋은 경험과 개선이 필요한 경험을 안전하게 기록할 공간이 부족하다.
- 기존 커뮤니티의 경험담은 흩어져 있고 실제 방문 여부를 확인하기 어렵다.
- 신원이 노출되거나 음식점이 작성자를 추정할 수 있다는 우려가 있다.
- 자신의 기록이 음식점 리포트와 변화에 어떻게 기여했는지 확인하기 어렵다.

### 소비자

- 기존 리뷰는 맛과 배달 만족도 중심이어서 픽업 공간, 포장, 주문 관리 등 운영 정보를 알기 어렵다.
- 감정적인 리뷰를 일일이 읽어야 하며 표본 수와 최신성을 판단하기 어렵다.
- 단일 별점보다 최근 여러 방문에서 반복 관찰된 정보를 필요로 한다.

### 음식점

- 단편적인 비난이 아닌 구조화된 개선 신호를 받기 어렵다.
- 잘못 연결된 장소, 개인정보, 중복 또는 허위 가능성이 있는 정보에 정정을 요청할 공식 절차가 필요하다.

### 서비스 운영자

- 검증되지 않은 경험담은 신뢰할 수 있는 데이터 자산이 되기 어렵다.
- 리뷰가 여러 음식점에 분산되면 공개 가능한 리포트를 만들기 어렵다.
- 익명성, 방문 검증, 검수, 신고 및 정정 절차가 없으면 지속 가능한 서비스를 운영하기 어렵다.

## 3. 핵심 사용자

1. **리뷰 작성자**: 카카오 계정으로 가입하고 배달 완료 화면을 통해 방문을 인증한 뒤 리뷰를 작성한다.
2. **소비자**: 로그인 없이 음식점을 검색하고 공개 기준을 충족한 운영 리포트를 확인한다.
3. **음식점 관계자**: 장소 오연결, 개인정보, 허위 가능성 등에 대해 정정을 요청한다.
4. **관리자**: OCR 예외, 자유 의견, 신고, 위험 계정, 정정 요청을 검수한다.

## 4. 제품 원칙

- 계정의 라이더 자격을 별도로 심사하지 않는다.
- 카카오 로그인 회원에게 방문 인증 기능을 즉시 제공한다.
- 정식 리뷰는 유효한 방문 인증을 통과한 경우에만 생성할 수 있다.
- 로그인 사용자는 방문 인증 전에 비공개 리뷰 초안을 작성할 수 있지만, 초안은 정식 리뷰가 아니며 공개·집계되지 않는다.
- 하나의 방문 증빙은 하나의 음식점 리뷰에만 사용할 수 있다.
- 맛이나 인기보다 픽업 과정에서 직접 관찰 가능한 운영 경험을 기록한다.
- 종합 별점과 음식점 순위를 제공하지 않는다.
- 서비스의 목적은 비난이 아니라 반복 관찰과 변화를 기록하는 것이다.
- 소비자와 음식점에 리뷰 작성자의 신원을 공개하지 않는다.

## 5. 핵심 사용자 흐름

### 5.1 회원가입과 온보딩

1. 사용자가 카카오 소셜 로그인을 완료한다.
2. 필수 약관, 개인정보 처리방침, 방문 증빙 처리 정책에 동의한다.
3. 별도 초대코드나 라이더 자격 심사 없이 회원 상태가 `ACTIVE`가 된다.
4. 앱은 다음 세 가지를 안내한다.
   - 가입 후 바로 방문 인증을 시작할 수 있다.
   - 음식점마다 배달 완료 화면을 통한 방문 인증이 필요하다.
   - 원본 증빙은 공개되지 않으며 처리 후 삭제된다.

### 5.2 리뷰 초안

1. 필수 약관에 동의한 회원은 파일럿 지역의 음식점을 선택한다.
2. 회원은 방문 인증 전에 6개 평가 항목과 선택 자유 의견을 비공개 초안으로 저장하고 수정할 수 있다.
3. 초안은 일부 항목이 비어 있어도 저장할 수 있지만, 제공된 응답 값과 자유 의견 길이는 동일한 입력 규칙으로 검증한다.
4. 초안은 작성자 본인만 조회·수정할 수 있으며 공개 리포트, 작성자 수, 기여 지표와 관리자 검수에 포함하지 않는다.
5. 초안은 방문 인증을 대신하지 않으며, 향후 유효한 `WriteGrant`와 함께 정식 리뷰로 전환될 때 6개 필수 문항을 모두 검증한다.

### 5.3 방문 인증

1. 회원이 배달 완료 화면을 업로드한다.
2. 서버가 이미지 형식, 크기와 업로드 권한을 검증한다.
3. OCR이 배달 앱, 완료 상태, 음식점명, 완료 시각, 주문 식별 정보를 추출한다.
4. 서버가 다음 조건을 검증한다.
   - 완료 시각이 최근 7일 이내인가.
   - 음식점이 파일럿 중심점 반경 3km 안에 있는가.
   - 동일 주문 또는 동일·유사 이미지가 이미 사용되지 않았는가.
   - 추출된 음식점과 카카오 장소가 신뢰도 기준 이상으로 일치하는가.
5. 자동 판정이 어려우면 관리자 수동 검수로 전환한다.
6. 방문이 승인되면 해당 음식점에서만 사용할 수 있는 1회용 글쓰기 권한을 발급한다.
7. 글쓰기 권한은 24시간 후 만료되고 리뷰 제출 시 즉시 소진된다.

자동 OCR은 배달의민족 완료 화면을 우선 지원한다. 지원하지 않는 배달 앱은 관리자 수동 검수 대상으로 접수한다.

OCR 공급자와 LangChain 계열 framework의 실행 형태는 방문 인증 단계 착수 시 정확도, 운영 복잡도와 비용을 비교해 ADR로 확정한다.

### 5.4 정식 리뷰 작성

리뷰는 다음 다섯 가지 응답 중 하나를 선택하는 6개 필수 문항으로 구성한다.

- 매우 좋음
- 좋음
- 개선 필요
- 큰 개선 필요
- 관찰하지 못함

평가 항목:

1. 픽업 공간 청결
2. 포장 안정성
3. 주문 준비 상태
4. 주문 확인·전달 정확성
5. 직원 응대
6. 라이더 존중

`관찰하지 못함`은 해당 항목의 집계 분모에서 제외한다.

자유 의견은 선택 사항이며 최대 200자로 제한한다. 사용자는 직접 관찰한 사실만 작성해야 하며 실명, 연락처, 주문번호, 고객 정보, 혐오 표현과 단정적인 범죄·위생 주장을 작성할 수 없다. 자유 의견은 관리자 승인 후 공개한다.

정식 리뷰는 유효한 `WriteGrant`와 본인 소유 초안을 사용해 생성한다. 초안 전환, `WriteGrant` 확인·소진과 리뷰 생성은 하나의 트랜잭션에서 원자적으로 처리한다.

### 5.5 기여 피드백

리뷰 제출 후 다음 정보를 제공한다.

- 누적 방문 인증 리뷰 수
- 기여한 음식점 수
- 해당 음식점의 공개 기준까지 남은 작성자 수
- 내가 참여한 음식점 리포트의 공개 여부
- 자유 의견 검수 상태

금전성 포인트와 작성자 순위는 MVP에 포함하지 않는다.

### 5.6 소비자 리포트 조회

1. 소비자는 로그인 없이 파일럿 지역의 음식점을 검색한다.
2. 검색 결과에서 `리포트 공개`, `데이터 수집 중`, `리뷰 없음` 상태를 확인한다.
3. 공개 리포트에서 최근 90일의 작성자 수, 마지막 갱신일, 항목별 응답 분포와 변화를 확인한다.
4. 각 수치 옆에서 평가 기준과 표본 수를 확인한다.

리포트는 주방 전체나 식품 안전을 인증하는 결과가 아니라 픽업 과정에서 관찰된 운영 경험임을 명시한다.

## 6. 리포트 공개 및 집계 정책

- 음식점 리포트는 최근 90일 내 서로 다른 방문 인증 작성자 5명부터 공개한다.
- 개별 항목도 `관찰하지 못함`을 제외한 서로 다른 작성자 5명 이상일 때 공개한다.
- 긍정 응답 비율은 `매우 좋음 + 좋음`으로 계산한다.
- 현재 30일과 직전 30일에 각각 작성자 5명 이상이 있을 때만 변화 추이를 표시한다.
- 같은 작성자가 같은 음식점에 여러 번 리뷰할 수 있지만 하루 1건, 최근 90일 최대 3건만 공개 집계에 반영한다.
- 표본 부족은 낮은 점수로 표시하지 않고 `데이터 수집 중`으로 표시한다.
- 종합 별점, 음식점 순위, 최악·최고 음식점 목록을 만들지 않는다.

## 7. 익명성, 보안 및 어뷰징 방지

- 카카오 닉네임, 프로필, 외부 계정 식별자를 공개하지 않는다.
- 관리자만 업무상 필요한 범위에서 작성자와 리뷰의 내부 연결을 확인할 수 있다.
- 주문 식별 정보는 원문 대신 HMAC 해시로 저장한다.
- 원본 이미지 해시와 perceptual hash를 저장해 자르기·리사이즈된 중복 이미지도 탐지한다.
- OCR 성공 원본은 추출 완료 후 즉시 삭제한다.
- OCR 실패 또는 수동 검수 원본은 암호화하여 최대 72시간 보관한다.
- 24시간 내 20건을 초과한 증빙은 자동 승인하지 않고 위험 검수 큐로 보낸다.
- 동일 주문 공유, 반복 거절, 비정상 제출 패턴이 발견되면 계정과 관련 리뷰를 보류할 수 있다.

## 8. 신고 및 음식점 정정 요청

- 소비자는 공개된 자유 의견을 신고할 수 있다.
- 음식점 관계자는 장소 오연결, 개인정보, 중복, 허위 가능성에 대해 정정을 요청할 수 있다.
- 음식점은 점수를 직접 수정하거나 작성자에게 공개 답글을 달 수 없다.
- 관리자는 필요한 경우 특정 자유 의견만 임시 비공개할 수 있다.
- 모든 관리자 결정은 처리자, 시각, 사유와 변경 전후 상태를 감사 로그로 남긴다.
- 정정 요청 처리 목표는 영업일 기준 5일이다.

## 9. 지역 파일럿

- 기간: 4주
- 범위: 운영자가 설정한 중심점 반경 3km
- 목표 참여자: 방문 인증 리뷰를 1건 이상 작성한 사용자 30명
- 목표 리뷰: 유효한 방문 인증 리뷰 300건
- 목표 음식점: 공개 리포트 20곳 이상

성공 지표:

- 방문 인증 후 리뷰 완료율 70% 이상
- 2주 이상 반복 작성자 비율 50% 이상
- OCR 자동 판정률 80% 이상
- 음식점 자동 오연결률 1% 미만
- 로그인부터 첫 리뷰 제출까지 중앙값 3분 이하

## 10. MVP 범위

### 포함

- 카카오 로그인
- 회원 약관 동의와 서비스 세션
- 음식점 검색과 지역 제한
- 로그인 사용자의 비공개 리뷰 초안 작성·수정
- 증빙 이미지 업로드
- 배민 완료 화면 OCR과 수동 검수
- 방문별 1회용 글쓰기 권한
- 구조화 리뷰와 자유 의견
- 관리자 검수, 신고, 정정 요청
- 음식점별 집계 리포트
- 서버 REST API와 OpenAPI 명세

### 제외

- 별도 라이더 자격 인증
- 초대 전용 가입
- 카카오 외 소셜 로그인
- 실시간 GPS 검증
- 종합 별점과 음식점 순위
- 소비자 리뷰와 댓글
- 음식점 공개 답글
- 금전성 포인트와 리워드
- AI의 자동 게시·삭제 결정
- 전국 서비스
- 원본 증빙 장기 보관
- 서버 API 완성 전 React Native 화면 구현

## 11. 개발 우선순위

1. Spring Boot 서버 기반과 데이터베이스
2. 카카오 로그인, 온보딩 토큰과 인증·인가
3. 음식점과 파일럿 지역 API
4. 로그인 사용자의 비공개 리뷰 초안 API
5. 증빙 업로드와 OCR provider 선정·방문 인증
6. 1회용 글쓰기 권한과 정식 리뷰 전환 API
7. 집계 리포트 API
8. 관리자 검수·신고·정정 API
9. 보안, 통합, 성능 테스트와 OpenAPI 계약 확정
10. React Native 크로스 플랫폼 앱
